# 刹不住的 1612N

一个用 Go 写的终端小游戏。

你开着车在公路上高速飞驰，前方**前车**就在眼前——**全力刹车**！

问题是：这辆车的刹车踏板在受力 **超过 1612 N** 时会「啪」地一声断掉。
踩轻了追尾；踩猛了断踏板。不过别慌：只要断板那一刻还没到「立刻就会撞上」的地步，
（或者系统预测到你 **3 秒内必定追尾**，哪怕踏板还没断）
你的车会**接管前方那辆会飞的前车**——拉升、下降，从它头顶飞过去就行。
**只要没有撞上前车，就算你赢**，只是峰值奖励没了。

## 玩法

刹车力是一个**连续量**，不是一格一格的：

| 按键 | 作用 |
| --- | --- |
| **按住空格** | 踩下刹车踏板，力以 450 N/s 上涨 |
| **松手** | 抬起踏板，力以 400 N/s 衰减 |
| **W / S** | 断板后的飞车段：拉升 / 下降 |
| `R` | 结束后再来一次 |
| `Q` / `Ctrl+C` | 退出 |

- 力在表盘上平滑地涨落 —— 盯着它，在冲过 1612 N 之前松手。
- 力一旦 **> 1612 N**：踏板断裂，刹车力瞬间归零，只剩滑行阻力（滚阻 + 风阻）。
  这时按「到前车还剩多久」分流：
  - **来得及飞**（`剩余距离 / 当前速度 > 0.5 s`）→ 先进入 **3 秒接管缓冲**（物理冻结，
    只走倒计时，画面会提示距离和剩余秒数），再接管会飞的**前车**，进入飞车段；
  - **来不及飞** → 直接撞上前车，失败。
- **踏板没断也会自动接管**：每帧都会按当前速度 + 当前踏板力外推 3 秒（`AutoFlyHorizon`），
  只要预测到「照这样开必然撞上前车」，同样先进入 3 秒接管缓冲，再接管飞车。
  也就是说救不回来的时候，系统会提前把方向盘交给飞行汽车。
- 不敢踩、没在前车前停住、又没飞越，才是真失败。
- 从 0 一直按住不松手，3.58 s 就会踩断（力涨到 1350 N 起开始报警，留给你约 0.58 s）。
- 巡航段（开头那 2.4 s）刹车还踩不下去，等「!! 前方有情况 !!」亮起再踩；
  想抢时间可以提前按住，刹车点一到立刻生效。

### 飞车段（断板后的第二回合）

- 断板后会先**冻结 3 秒**（`SnapPause`）：车不前进、评分计时也不走，画面只剩接管倒计时，
  用来给你看清「距前车还有多远」、想好什么时候拉。缓冲结束才真正开始飞车段。
- **自动接管**（踏板没断、但 3 秒内必撞）走同一套缓冲与飞车段，只是结算文案不写「踏板已断」，
  评分按飞越那套算。
- **W 拉升 / S 下降**，`MaxAltitude` 3 m，升/降都是 6 m/s。
- **悬空时长上限 3 s**：只有在空中才计时，什么键都不按会**悬停**（保持高度，但照样耗悬空）。
- 悬空耗尽 → **强制下降**（拉升键失效），并进入 **2 s 冷却**；冷却结束后悬空回满，可以**再次升起**。
- **判定**：到达前车位置时高度 ≥ 前车高度（1.5 m）→ **飞越成功（赢）**；
  高度不够 → 撞上前车（输）。断板后靠滑行在**前车前停住**，也算赢（没撞上就是赢）。
- 悬空只有 3 s，所以要**卡在飞越那一刻再拉升**：拉太早悬空会在飞越前耗尽，被迫掉下来撞车；
  拉太晚则来不及时高度不够。

> **松手后力还会多涨约 50 N**（终端靠连发间隔推断松手，总有一点延迟）。
> 所以别贴到 1612 才松——经验上骑到 **1560 N 左右**就该抬脚了。

> 终端拿不到可靠的「松键」事件，所以游戏靠键盘连发的时间间隔来推断踏板是否按住：
> 间隔小于 250 ms 的算同一次按住。新的一次按压有宽限期——**开局或完全松开后的第一脚
> 给 650 ms**（既让单点也有可见的蓄力过程，也正好桥接住 Windows 首次连发前约 500 ms
> 的延迟），**已经在蓄力时最多只给 260 ms**。所以即使你的键盘不连发、只能一下下点，
> 力也是可控的小步长，而不是每点一下窜 +390 N。飞车段的 W/S 用的是同一套推断。

## 评分

- **正常刹停**（踏板没断）：**峰值刹车力越贴近 1612 N 得分越高**（8 次方曲线），
  外加**停车位置离前车越近越高**。
- **飞越取胜**（断板或自动接管后，从上方飞越）：单独一套评分 ——
  `1000 + 2000×高度余量 + 500×悬空节省比例`。想拿高分要**飞得高**又**省悬空**，
  两者互相拉扯（飞得高就得多耗悬空）。
- **断板后没飞、靠滑停蹭到前车前**：没撞上算赢，但峰值奖励作废，只剩停车位置的分，
  最高只能是 **C 级**。

评级：`C` < 1600 ≤ `B` < 2200 ≤ `A` < 2750 ≤ `S`

实测的几种打法（`go run . -sim` 闭环模拟真人，端到端跑通）：

| 打法 | 结果 |
| --- | --- |
| 不踩 | 5.18 s 后 101 km/h 撞前车 ❌ |
| 按死（断板后不拉升） | 7.82 s 断板后 51 km/h 撞前车 ❌ |
| 骑 ~800 N | 刹住了，峰值 938 N，余量 16.0 m，**C 级 1426** |
| 骑 ~1000 N | 峰值 1137 N，余量 29.7 m，**C 级 1436** |
| 骑 ~1200 N | 峰值 1338 N，余量 37.7 m，**B 级 1715** |
| 骑 ~1400 N | 峰值 1540 N，余量 42.2 m，**A 级 2624** |
| 骑 ~1430 N | 峰值 1570 N，余量 42.7 m，**S 级 2852** |
| 骑 ~1500 N 且手抖 | 峰值冲过 1612 N 断板，飞车没拉起来 → **撞前车** ❌ |
| 稳手贴线 ~1500 N | 峰值 1593 N，余量 44.9 m，**S 级 3041** |
| 稳手贴线 ~1540 N | 峰值冲过 1612 N，**断板撞前车** ❌ |
| 键盘不连发、只能手点 ~1400 N | 峰值 1567 N，余量 42.4 m，**S 级 2827** |
| 断板后**及时拉升**飞越 | 峰值 1613 N，**飞越 ✔ S 级 3417** |
| 断板后**拉太早**（悬空耗尽掉下来） | **撞前车** ❌ |
| 断板后**贴脸才拉**（高度余量小） | **飞越 ✔ B 级 1723** |
| 不踩，但会自动接管并拉升 | **自动接管飞越 ✔ S 级 3419** |

> 只要全程平均踩到约 800 N 就一定能刹住；再往上骑纯粹是为了分数。
> 断板也不必慌：算好距离，在飞越前那一刻拉升。

物理：`减速度 = (踏板力 × 助力比(6) + 滑行阻力) / 质量(1260 kg)`，其中滑行阻力
`= 滚阻 150 N + 风阻 0.42·v² N`（108 km/h 时约 530 N，折合 0.42 m/s²）。所以踏板断了、
或者干脆没踩，车也会缓慢减速，只是这点阻力远不够在前车前停下 —— 断板后真正救命的是飞车段。
初速 30 m/s（约 108 km/h），前车在 150 m 外 —— 加上从 0 建力的过程，
全程平均约 800 N 就刹得住；想拿高分则要把峰值压在 1500–1600 N 这条细线上。

## 调难度

所有数值都在 `physics.go` 顶部的 `Phys`：

```go
ObstacleDistance   // 到前车的距离，默认 150；调小更难（更早、更狠地刹车）
StartSpeed         // 初速，默认 30
RampRate           // 力上涨的快慢，默认 450；调大更刺激也更难控
ForceDecay         // 力衰减的快慢，默认 400；调大就更得一直踩着
Limit              // 踏板极限，默认 1612
RollForce          // 恒定滑行阻力，默认 150
AeroC2             // 风阻系数 ½ρCdA，默认 0.42
// —— 飞车段 ——
FrontCarHeight     // 前车高度，默认 1.5；飞越时高度必须 ≥ 它
MaxAltitude        // 最高可拉升高度，默认 3
ClimbRate/DescendRate // 升/降速率，默认 6
MaxHover           // 单次悬空上限，默认 3（s）；调小更考验拉升时机
HoverCooldown      // 悬空耗尽后的冷却，默认 2（s）
FlyArmTTC          // 断板时「到前车时间」≤ 它就直接撞（来不及飞），默认 0.5
SnapPause          // 断板后接管前的冻结缓冲 (s)，默认 3
AutoFlyHorizon     // 预测「这么多秒内必然撞上」就自动接管（踏板没断也接管），默认 3
```

按键手感的时间参数在同文件的 `Pedal` 里（连发判定、冷/热按压宽限期）。
改完跑一遍 `go run . -sim`，就能看到各档打法的余量和得分，
用来确认新的难度曲线是否还有梯度、S 是不是仍然只有贴线（或漂亮地飞越）才拿得到。

## 结构

```
main.go             入口、主循环（60Hz 渲染 + 1/60 固定步长累加器）、生命周期（-sim 跑校准脚本）
game.go             状态机（按阶段拆分 tick，含飞车段）、按键时间推断、音效、每帧视图
physics.go          常量、积分原语与各阶段步进（stepPhysics / stepFlying）、评分、踏板宽限期
render.go           ANSI 渲染与各阶段版面（统一 frameW + 截断补齐 + 各阶段统一表盘）
text.go             终端文本度量与格式化（CJK 列宽、截断/补齐、数字格式）
input.go            原始模式按键（golang.org/x/term）
console_windows.go  Windows 控制台 VT 处理 / UTF-8 输出准备（非 Windows 为空实现）
sim.go              闭环模拟：校准难度、评级线回归验证
physics_test.go     物理/评分/悬空冷却单测、标定表参考解
game_test.go        游戏流程测试（巡航→刹车→断板→飞车→撞车/飞越→重开）
```

## 实现说明

- 依赖只有 `golang.org/x/term`（raw 模式 / 终端尺寸）和 `golang.org/x/sys`（Windows 控制台），
  没有引入完整 TUI 框架：这游戏的「靠连发间隔推断按住」和 60 Hz 全屏重绘都要精确的按键时序，
  框架的批处理/渲染节流会改变手感，而渲染本来就是 ANSI 字符串，cell 抽象没有收益。
- Windows 细节：`x/term` 的 `MakeRaw` 只管输入侧的 VT；程序启动时自己打开 stdout 的
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING` 并把输出代码页切到 UTF-8（退出时还原），
  这样老 conhost 也能正常显示颜色和中文。若控制台被策略禁用了 VT 会显示乱码，
  换成 Windows Terminal 即可。
